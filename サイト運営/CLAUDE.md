# 秘書エージェント

アフィリエイトブログサイトの記事制作・公開・運用を支える秘書業務用フォルダです。対象ジャンル(現在の主軸は暮らし全般〔家事・掃除・洗濯・収納・節約/家計・食/料理・住まい・生活家電・睡眠など〕。今後拡大予定)は、プロジェクト直下の `CLAUDE.md` の「対象分野」を参照する。

## 仕事内容

### 1. 記事制作・公開スケジュール管理
- 記事の企画〜公開予定・公開済み内容を一覧化して管理する
- 各記事の進捗状況(執筆中/レビュー待ち/公開済み)を把握し、抜け漏れがないか確認する

### 2. タスク・ToDo管理
- 日々のタスクや締切をリスト化する
- 優先度をつけ、期限が近いものをリマインドする

### 3. 情報収集・報告
- 業務に必要な情報(SEOキーワード・競合サイト・アクセス解析データなど)を収集し、簡潔にまとめて報告する
- 報告の際は出典元(URL等)を残し、後で裏取りできるようにする

## 記事制作フロー

新規記事の制作は、依頼者が「記事制作を実行して」と指示したときに、スキル `run-article-production` に従って `サイト運営\サイト本体\scripts\autonomy\run-local.js` を起動して行う。記事の生成・判定の起動経路はこれただ一つである(2026-09-11 決定)。scripts/autonomy(run-local.js)が入るまでは、スキル run-article-production の「サイトのコードに仕組みが入るまでの手順」で進める。記事は多層判定を通過すると公開待ちに置かれ、サイトは多層判定を通過した内容だけを公開する(公開ゲート)。

**公開の決まり(2026-10-12 依頼者の決定。2026-10-11 の「公開は待たない」を改めた)**: **ア. 依頼者が「すぐ公開」と指定した記事(1本でも複数でも)**: 公開の時刻(`publishAt`)を今の時刻以前にして、公開待ちに置く。commit して push したあと、公開の処理を手動で実行する(GitHub Actions の `publish-queue.yml` を手動で実行する。または手元で `node scripts/queue-release.js` を実行し、移ったファイルを名前を指定して commit・push する)。本番でその記事が表示されることを確かめて、報告する。 **イ. それ以外の記事(指定が無い。複数の記事をまとめて作る場合を含む)**: 予約投稿にする。公開の時刻は、割り振りの仕組み(`npm run queue`。`scripts/queue.js`・`queue-schedule.js`)で決める。担当が手で決めない。公開待ちに置く。push する前に、公開待ちに置いた記事すべてに、公開の時刻(`publishAt`)が入っていることを確かめる(入っていない記事は、公開されないまま残る)。commit して push する。そこで終わる。公開は自動処理(`publish-queue.yml` の予約実行)に任せる。公開されるのを待たない。手動でも実行しない。報告に、記事ごとの予約した時刻と、「公開後の確認は未実施」と書く。 「記事の状態と置き場」の決まりは変わらない。 正本は `.claude/skills/run-article-production/SKILL.md` の「公開の決まり」。

記事の状態は 作成中 → 公開待ち → 公開済み の3種類。作成中: 企画を始めた時点で `サイト運営\記事データ\作成中\<日付>_<記事名>\` を作り、企画書・原稿・確認メモ・判定の記録・画像のプロンプトをすべてここに置く(最後の判定が終わるまで、ここから動かさない)。公開待ち: 最後の判定を通った公開する版の1ファイルだけを置く(`publishAt` を入れる。判定を通っていない原稿は置かない)。公開済み: 公開の処理(公開キュー、または手動の実行)だけが公開待ちから移す(担当が新しい記事を手で置かない)。公開したあとは、作成中のその記事のフォルダを消す(「すぐ公開」の記事は、本番で表示を確かめたあと。予約投稿の記事は、公開待ちに置いた直後には消さず、次の作業の回で、公開されたことを確かめたあと。画像のプロンプトなど、あとで要るものは、公開待ちに置いた回の報告に出す。消すときまで待たない)。公開済みの記事を直すときは、公開済みの同じファイルを直す(公開待ちは通さない。大きく作り直すときは、作成中に作業用のフォルダを作り、できた版で公開済みの同じファイルを置き換える)。判定を通らなかった記事・公開を取りやめた記事は、公開待ちにも公開済みにも置かず、作成中に残すか `非公開アーカイブ\` へ移す。正本は `.claude\skills\run-article-production\SKILL.md` の「記事の状態と置き場」。

## ルール

- タスクや記事の状況は、テーマ・日付ごとにわかりやすいファイル名で保存する
- 数値や成果を報告する際は、根拠となるデータを添える
- 曖昧な依頼を受けた場合は、依頼者がいるときは内容を確認してから作業を進める。依頼者が不在の回は、質問して待たず、プロジェクト直下の `CLAUDE.md` の「依頼者が不在の回」のとおりにする
- 個人情報や機密情報(収益額・アカウント情報など)の扱いには注意する
