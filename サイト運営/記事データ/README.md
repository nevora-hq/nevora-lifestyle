# 記事データ受け渡しフォルダ

記事の状態は 作成中 → 公開待ち → 公開済み の3種類です。サイト本体(Next.js)が取り込むのは `公開済み\` だけです。

| 状態 | 置き場 | 置くもの |
|---|---|---|
| 作成中 | `作成中\<日付>_<記事名>\` | 企画書・原稿・確認メモ・判定の記録・画像のプロンプト(すべてこの中)。git に入れない(`.gitkeep` だけ残す) |
| 公開待ち | `公開待ち\` | 最後の判定を通った公開する版の1ファイルだけ。`publishAt` を入れる |
| 公開済み | `公開済み\` | 公開の処理が公開待ちから移した記事。サイトに出る |

## 運用ルール

- 作成中: 企画を始めた時点で記事ごとのフォルダを作り、企画、判定、執筆、仕上げ、最後の判定が終わるまで、ここから動かさない
- 公開待ち: 判定を通っていない原稿は置かない。ファイル名は `YYYY-MM-DD_テーマ.md`
- 公開済み: 公開の処理(`publish-queue.yml` の自動実行、または `queue-release.js` の手動実行)だけが公開待ちから移す。担当が新しい記事を手で置かない
- 公開したあとは、作成中のその記事のフォルダを消す(「すぐ公開」の記事は、本番で表示を確かめたあと。予約投稿の記事は、公開待ちに置いた直後には消さず、次の作業の回で、公開されたことを確かめたあと。画像のプロンプトなど、あとで要るものは、公開待ちに置いた回の報告に出す。消すときまで待たない)
- 公開済みの記事を直すときは、公開済みの同じファイルを直す(公開待ちは通さない)。大きく作り直すときは、作成中に作業用のフォルダを作って進め、できた版で公開済みの同じファイルを置き換える
- 判定を通らなかった記事・公開を取りやめた記事は、公開待ちにも公開済みにも置かず、作成中に残すか `非公開アーカイブ\` へ移す
- `キーワード調査\`・`振り返り\`・`非公開アーカイブ\` は記事の状態ではないので、この流れとは別に扱う
- この直下の `2026-09-02_家庭内の事故_…`・`2026-09-08_火災統計_…` は、記事ではなく調査の資料(記事の根拠データの照合メモ・集計)。サイトには出ない

正本は `.claude\skills\run-article-production\SKILL.md` の「記事の状態と置き場」です。
