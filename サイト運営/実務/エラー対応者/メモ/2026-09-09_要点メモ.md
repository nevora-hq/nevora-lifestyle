# 2026-09-09 要点メモ(画像リンク切れ対応)

- **根本原因**: 記事「火事の原因は家の中と外で違う」のthumbnailはfrontmatterにパス文字列だけが書かれ、対応するwebpファイルが`public\images\articles\`に一度も配置されていなかった。生成済みの元画像3枚は画像ライブラリ直下に置かれ、image-selector/image-placerが走査する`記事用`サブフォルダに入っていなかったため、両エージェントに一度も拾われないまま公開フローが進んだ
- **検証の盲点**: `scripts/verify-article.js`項目16は従来「thumbnailフィールドが空文字でないか」しか見ておらず、参照先ファイルが実在するかは検証していなかった。フィールドが非空であれば合格していたため、パスだけ書いて画像未配置という状態を機械検査ですり抜けていた
- **修正**: 項目16にthumbnail・本文中`![]()`参照先の実ファイル存在チェックを追加(ブロッキング)。既存の生成済み画像(ライブラリ直下に放置されていた元PNG)をwebp変換し正しいパスへ配置して修正。`npm run verify:all`(確定稿14本・公開済み1本)は全てoverall=Yesを確認。加えてサイト本体`content/articles`配下の公開済み全記事(約40本)にも項目16を個別実行し、他に同種の欠落がないことを確認した(`npm run verify:all`自体は記事データ側の2フォルダのみを対象にしており、サイト本体`content/articles`をカバーしていない点に注意。今後同種の項目追加時はこの手動補完が必要)
- **副次的な発見**: 直前に「publish」された「備蓄は水の量から逆算する」記事は、実はまだ`サイト運営\サイト本体\content\articles\`へ配置されておらず(`確定稿`フォルダに留まったまま)、サイト上には公開されていなかった。画像自体は存在し問題なしだが、「publishコミット」が実際のサイト反映を意味するとは限らない運用上の混同があるため、次にpublisherが確定稿一覧を確認する際に見落とさないよう申し送り
- **再発防止**: image-selector(走査対象は`記事用`直下のみで、直下に無ければライブラリ直下も確認するよう追記)、image-placer(パスを書くのは実配置後のみとする原則を明記)、publisher(公開直前にthumbnail/本文画像の実ファイル存在確認を必須化)の3エージェント定義を更新
- **教訓**: frontmatterのフィールドが「非空」であることと「参照先が実在する」ことは別物であり、パス文字列を書く工程と実ファイルを配置する工程が別エージェントに分かれている場合、機械検査は必ず実ファイルの存在まで見る設計にする
