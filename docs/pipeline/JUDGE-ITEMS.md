**この文書が、企画の判定・通読判定の項目表の正である。**回ごとの共通の指示(`サイト運営/記事データ/作成中/_共通の指示_第N回_段階1_企画の判定_…`・`_段階2_通読判定_…`)は、項目をここから写して使う(末尾の D の手順)。**項目の全文はこの文書だけに置く**(共通の指示に書き換えて持たない)。項目を足す・変えるときは、この文書だけを直す。見方の本文は次の3か所にあり、この表には書き写さない。
- 書き手の規則: `.claude/agents/writer.md`(規則番号で参照する)
- 目で確かめること(題・見出し・本文・部品の確かめ方): `.claude/agents/nevora-pipeline-verifier.md` の節「目で確かめること」。以下「確かめ表」と呼ぶ。`verify-article.js` の判定表(ブロッキング29項目)とは別で、ここでは通読判定の項目12・15・16・17が、その該当行を Yes/No にする
- 部品の数え方: `afterParagraph` は確かめ表の該当行と writer.md 規則32(a)。判定は `サイト運営/サイト本体/scripts/verify-article.js` が Yes になるかで見る(文面と食い違うときは verify-article.js を正とし、No にしない)

**指摘の分け方(2026-10-11 依頼者の決定)。** 判定する担当は、No・指摘ごとに、次のア・イ・ウのどれかを付けて返す(定義は `current-rules.json` の `judgmentPrinciples.findingClasses`、判定の流れは `.claude/skills/run-article-production/SKILL.md` の「判定の流れ」)。
- **ア(差し戻す)**: 内容が変わる指摘。事実、条件、手順、結論、読者への約束が変わるもの。
- **イ(まとめて直す)**: 形と書き方の指摘。字数、文の数、語尾、強調の数、部品の並び、sectionAlternate、表記など。差し戻しに数えない。仕上げで1回にまとめて直し、直していない担当が、内容が変わっていないことを1回確かめる。残った形の指摘はもう1回だけ直し、それでも残れば報告に書いて先へ進む。
- **ウ(差し戻さない)**: 出典の印の欠け、企画書と原稿の食い違い。その場で直す(食い違いは企画書の側を直す)か、報告だけにする。
- 「No なしまで繰り返す」は、アの No について言う。イの No は上のとおり、まとめて直して確かめ、もう1回だけ直す。
- 差し戻したあとは、直した所に関係する判定・項目だけをやり直す。差し戻しの上限は1つの記事で合計5回。
- **第3層(敵対的検証)**: 採用するのは、定義どおりの回数を実行して過半数の実行(3回なら2回以上、5回なら3回以上)に出た否定だけ。1回だけの否定と、判定が自分で「弱い」と書いた否定は採用しない。第3層による差し戻しは1つの記事で1回まで(合計5回のうち)。1回直したあとは第3層を理由に差し戻さず、最後の第3層の結果は報告だけにする。

判定の約束(共通)
- 各項目は Yes/No。No は「行・どの規則か・何が足りないか」を1行で書く。点数はつけない。
- 判定の担当は、判定する対象を書いていない者とする。対象のファイルを直さない(書いてよいのは判定のファイル1つだけ)。
