# サイト宣言文 vs 実態 監査

対象: `pages/about.js` `pages/privacy-policy.js` `pages/terms.js` `pages/contact.js`、記事frontmatter(`description`/`disclaimer`)、`docs/CONTRIBUTING.md`、`docs/project-state.md`(このサイトには無い。読まずに進める)

**本監査は検出・一覧化のみ。コード・コンテンツの編集は行わない。**

---

## 重大(審査リスク・信頼性リスク)

about.js等の宣言と現行運用の間に、AdSense審査を直接脅かすレベルの矛盾(運営者情報・広告表示・アフィリエイト開示が宣言どおりでない等)があるか。

---

## 中(修正推奨)

### 1. 記事frontmatterの`description`(meta description)が、体験談についての宣言と矛盾していないか

このサイトの`about.js`は「「個人の感想」と「確認された事実」を混在させず、体験談を事実のように扱いません」と宣言している(編集方針の節)。

一方、記事の`description`フィールドは`pages/posts/[slug].js`で`<meta name="description">`にそのまま出力され、Google検索結果のスニペットにもなる公開テキストである。ここに「実体験を交えて解説します」等、体験談を含むかのように読者に告知する文言があると、about.jsの宣言と食い違う。読者がGoogle検索結果でこの文言を見てクリックし、実際の本文に体験談がないと「サイトの説明と中身が違う」という印象を与えかねない。本文がB5ルールで一人称体験談を排除していても、`description`という**外部に露出するメタ情報**は別に確かめる。

見つけたら、公開済み(サイト上に実際に表示中)と公開待ち(未公開だが今後同じ文言のまま公開される見込み)に分けて、ファイルのパスと行を記録する。

### 2. `disclaimer`にCONTRIBUTING.mdで明示的に禁止された表現が残っていないか

`docs/CONTRIBUTING.md`セクション3は次のパターンを名指しで禁止している:
> 「実体験に基づく」「使用体験に基づく」等、記事の裏付けとして実在しない体験の存在を主張する記述を禁止。本文中だけでなく、免責文・注記…内の記述も対象に含む。

例: 「使用感・効果の実感は編集部内での個人的な使用体験に基づくものであり、…」のような`disclaimer`。下書き段階で未公開なら審査リスクにはなっていないが、公開待ちへ置く前・公開前に必ず修正が必要。

---

## 軽微

### 3. `disclaimer: none`のように、用途が文書化されていない値

`disclaimer: none`という値が入っている記事があるか。about.js・terms.js側にこのfrontmatter値自体への言及・説明がなければ、宣言文との直接的な矛盾はない(単に「免責注記なし」という記事側の内部管理値と推定される)。ただし他記事との一貫性(`disclaimer`フィールドの用途・命名)がドキュメント化されていない点は、将来的な誤用リスクとして記録しておく。

## 監査項目別の確認観点

| 項目 | 確認すること |
|---|---|
| (a) 体験談非掲載の宣言 vs 実態 | 本文(B5対応)と、**meta description(公開テキスト)**の両方で、体験談の宣言と食い違いが無いか(観点1) |
| (b) AI活用宣言 vs トーン・プロセス | about.jsのAI活用の宣言(このサイトでは「記事の下書き・図解・診断コンテンツの制作にAI(生成AI)を活用しています」、制作の流れの「執筆・構成(AI活用)」)と、実際のプロセスが一致しているか。「NEVORA編集部」等の主体表現が一貫しているか |
| (c) 一次情報優先ポリシー vs sources実運用 | about.jsの「一次情報(公的機関・学会・メーカー公式)を優先」と、編集部調査を載せる場合の「n数・調査方法・実施時期を明記」が、CONTRIBUTING.md 5節・17節の実運用方針と整合しているか |
| (d) updatedDate説明 vs 実運用 | about.jsの更新日の説明(内容に重要な変更があった記事には更新日を記載し、軽微な修正では最終更新日を変えない場合がある)が、CONTRIBUTING.md 12節の運用ルール(空更新をしない)と一致しているか。空更新があれば記事名を記録する |
| (e) 運営者情報の完全性(AdSense観点) | about.jsに屋号・運営者・連絡先メール・お問い合わせへの導線があり、contact.jsに連絡手段が明示されているか。所在地が「非公開」でも、問い合わせ手段が明示されていれば最低要件は満たす |
| (f) その他 | about/privacy-policy/terms間の相互リンク・免責事項の重複表記に矛盾が無いか |

## 総括

発見件数(重大・中・軽微ごと)と、優先度の高い順の対応候補を書く。編集は行わないため、対応は別タスクで実施すること。
